# MCP Java SDK — entry-point roles

Parser: `src/breezeai_cog/parsers/java_mcp/tools.py` (additive detector); the JSON-schema reader is in `parsers/jvm_mcp_common.py`, shared with [`kotlin-mcp`](kotlin-mcp.md) · Rules: [entry-point contract](../architecture/entry-points.md) · Tests: `tests/unit/test_roles_java_mcp.py`

A tool specification of the MCP Java SDK (`io.modelcontextprotocol`), written in Java. The same construct written in Kotlin is in the [Kotlin table](kotlin-mcp.md), with the same `framework: java-mcp`. The fields of an `mcp_tool` record, how `params` is read and limited, and what an incremental sync does are the same for every MCP framework: [entry-point contract, MCP tools](../architecture/entry-points.md#mcp-tools).

| Construct | Role | Record | Why |
|---|---|---|---|
| Java `new McpServerFeatures.SyncToolSpecification(tool, handler)` / `AsyncToolSpecification`, or their `builder().tool(…).callHandler(…).build()` (MCP Java SDK, `io.modelcontextprotocol`) | Binding | `mcp_tool`, `framework: java-mcp`, at the constructor / `build()` call; the tool is `new McpSchema.Tool(name, description, schemaJson)` or `McpSchema.Tool.builder().name(…).description(…).inputSchema(…).build()`, inline or a local variable declared once in the file; `description` only from a literal (another `Tool` constructor overload: none); `params` from a JSON-schema string literal, else empty (unknown); `handler` = the method of a method reference (`this::calc`), a lambda gives only its line | A tool specification is server-side by definition |
| `McpServer.sync(transport)….tool(tool, handler)` / `.toolCall(tool, handler)`, also `McpServer.async(…)` (MCP Java SDK) | Binding — only on a chain that starts at `McpServer.sync(` / `McpServer.async(`, in a file using `io.modelcontextprotocol` | `mcp_tool`, `framework: java-mcp`, at the `.tool` / `.toolCall` name (its line); the tool and `handler` read as for a tool specification above (`new McpSchema.Tool(…)` / `Tool.builder()…build()`, inline or a local variable declared once) | The server builder registers the tool directly |
| `.tools(spec, …)` on the server builder | Wiring | — | Each specification is recorded once, where it is built (row above) |
| `.tool(…)` on any other chain (a helper returning the builder, Spring AI's `ChatClient.prompt().tool(…)`) | None | — | Not proven an MCP server |
| A Spring AI `@McpTool` / `@Tool` method in the same file | None here | Recorded once, as [`spring-ai-mcp`](spring-ai-mcp.md) | Each tool is emitted once, by the package of its construct |
| A computed tool name (`new McpSchema.Tool(NAME, …)`, `.name(computed())`) | None | — | The tool exists, but its name is unknown |
| A `…ToolSpecification` in a file that does not use `io.modelcontextprotocol` | None | — | Not the SDK's class |
| `McpSchema.Tool.builder("name", …)` (SDK 1.0 builder that takes the name) | Binding | As the builder row: `endpoint` = its first argument; `builder(name, mapper, json)` reads the JSON schema; `builder(name, schemaMap)` → `params` `null` | |
| `new McpServerFeatures.Sync/AsyncResourceSpecification(resource, h)` / `…ResourceTemplateSpecification(template, h)` (also the stateless server's), the resource `new McpSchema.Resource("uri", "name", …)` / `Resource.builder("uri", "name")…build()` / `.builder().uri("…")…`, the template `new McpSchema.ResourceTemplate("tpl", …)` / its builder | Binding | `mcp_resource`, `framework: java-mcp`, at the specification; `endpoint` = the URI / template literal; `description` = `.description(…)`, or the constructor argument whose position the SDK fixes (`Resource(uri, name, title, description, …)`, `ResourceTemplate(tpl, name, description, mimeType, annotations)`); `params` `[]` for a `Resource`, a template's simple `{variables}`; handler as for a tool | `.resources(…)` / `.resourceTemplates(…)` / `.prompts(…)` take specifications only: each is recorded where it is built |
| `new McpServerFeatures.Sync/AsyncPromptSpecification(new McpSchema.Prompt("name", "desc", List.of(new PromptArgument("a", "d", true))), h)` (also `Prompt(name, title, description, arguments)` and `Prompt.builder("name")…`) | Binding | `mcp_prompt`; `params` from `List.of(…)` / `Arrays.asList(…)` of `PromptArgument(name, description, required)` (or its builder); `null` → `[]`; anything else → `null` | |
| A client: a name declared once in the file, typed `McpSyncClient` / `McpAsyncClient` or `var x = McpClient.sync(…)….build()` (also `this.x`) → `.callTool(new CallToolRequest("x", args))` (`(mapper, "x", json)`, `CallToolRequest.builder("x")` / `.builder().name("x")`) / `.readResource(new ReadResourceRequest("uri"))` / `.getPrompt(new GetPromptRequest("x", args))` | Outbound | `mcp_call`, `framework: java-mcp`, on the call's own statement; no file framework | A lambda parameter of the same name is another declaration (→ none). `clients.get(0).callTool(…)` (Spring AI's list of clients): which server it reaches is not in the code → none. Detector `java-mcp-client` (`parsers/java_mcp/clients.py`) |

Resource / prompt fields and `params`: [entry-point contract, MCP resources and prompts](../architecture/entry-points.md#mcp-resources-and-prompts); client calls: [MCP client calls](../architecture/entry-points.md#mcp-client-calls).
