# MCP server tools — entry-point roles

Parsers (additive detectors): `src/breezeai_cog/parsers/python_mcp/` (tools + the `mcp.servers` fact), `typescript_mcp/`, `java_mcp/` (tools + the `spring-ai.mcp-server` fact), `kotlin_mcp/` (tools + the same fact for Kotlin), `csharp_mcp/`, `go_mcp/`; shared fields in `parsers/mcp_common.py` · Rules: [entry-point contract](../architecture/entry-points.md) · Tests: `tests/unit/test_roles_mcp.py`

An MCP tool is an entry point an AI client calls by name. Every tool becomes one `mcp_tool` statement: `method: TOOL`, `endpoint` = the name clients call (after any rename), `framework` = the SDK, `handler` / `handlerLine` = the function that runs it, `description`, and `params` = `[{name, type, required, default, description}]` read from the input schema. `params` is `[]` only when the tool has no input schema (or an empty one); a schema that cannot be read whole (a variable, a spread, an unknown helper) leaves `params` empty (`null`, unknown) rather than a partial list.

A tool is recorded only when the object it is registered on is **proven an MCP server** and its name is a literal. Agent frameworks and chat clients use the same words (`@agent.tool`, Spring AI `@Tool`, `.tool(…)`), and a local class named `FastMCP` is not the SDK's — those are left alone.

| Construct | Role | Record | Why |
|---|---|---|---|
| Python `@<server>.tool` / `@<server>.tool(name=…, description=…)` on a function (FastMCP 2/3, `mcp.server.fastmcp`) | Binding | `mcp_tool`, `framework: fastmcp` (the standalone package) or `mcp-python` (the official SDK), decided by the file that builds the server, at the decorator; `endpoint` = `name=` / first positional string, else the function name; `description` = `description=`, else the docstring; `params` from the signature (`Annotated[T, Field(description=…)]` / `Annotated[T, "…"]` — only `Annotated`'s own metadata, not strings inside `T`; `= Field(…)`; defaults, including `Field(default=…)` inside `Annotated`; `Field(...)` / `Field(default=...)` is required); `self`, `*args`, `**kwargs`, `Context` (also `Context | None`, `Optional[Context]`) and the names in a literal `exclude_args=[…]` skipped (a non-literal `exclude_args` → `params` null); `enabled=False` → no record | `<server>` is a name assigned `FastMCP(…)`, a parameter annotated `FastMCP`, or a name imported from a module that assigns one — `FastMCP` itself imported from `fastmcp` / `mcp.server.fastmcp` |
| TypeScript / JavaScript `<server>.tool(name, [description], [zodShape], [annotations], callback)` (`@modelcontextprotocol/sdk`) | Binding | `mcp_tool`, `framework: mcp-sdk-ts`, at the call; an object is the params shape only when its values are zod chains (`.describe`, `.optional`, `.default`, `z.enum([…])`; `z.optional(X)` / `z.nullish(X)` optional with `X`'s type, `z.nullable(X)` still required); `z.object({…}).partial()` / `.deepPartial()` makes every param optional, and a method that changes the keys (`.extend`, `.merge`, `.pick`, `.omit`, `.partial({…})`) leaves `params` null | `<server>` is assigned `new McpServer(…)` (a variable, `this.x`, or a class field) or typed `McpServer`; a wrapped callback counts: the handler is the function literal inside (`withErrors(async (a) => …)`, its line), or a function of the same file passed alone (`withErrors(namedHandler)`); any other wrapper argument (`createHandler(apiClient)`) is not a handler — the record keeps only the wrapper's line |
| TypeScript `<server>.registerTool(name, {description, inputSchema}, callback)` | Binding | as above; `inputSchema` = a zod raw shape, `z.object({…})`, or a JSON-schema literal (`properties` / `required`) | |
| Java `@McpTool(name, description)` with `@McpToolParam(description, required)` (Spring AI MCP annotations) | Binding | `mcp_tool`, `framework: spring-ai-mcp`, at the annotation; `endpoint` = `name`, else the method name | MCP annotations by definition |
| Java `@Tool(name, description)` with `@ToolParam` (Spring AI) | Binding — **only** in a module whose build file (`pom.xml`, `build.gradle[.kts]` in the file's folder or an ancestor) declares a Spring AI MCP server starter as a dependency (a `<dependencyManagement>` entry or a Gradle `platform(…)` BOM does not count), and only for Spring AI's `@Tool` (imported from `org.springframework.ai.tool.annotation`, or fully qualified) | as above; `ToolContext` and MCP exchange / context parameters skipped | Without an MCP server, `@Tool` is a chat-client function |
| Java `new McpServerFeatures.SyncToolSpecification(tool, handler)` / `AsyncToolSpecification`, or their `builder().tool(…).callHandler(…).build()` (MCP Java SDK, `io.modelcontextprotocol`) | Binding | `mcp_tool`, `framework: mcp-java-sdk`, at the constructor / `build()` call; the tool is `new McpSchema.Tool(name, description, schemaJson)` or `McpSchema.Tool.builder().name(…).description(…).inputSchema(…).build()`, inline or a local variable declared once in the file; `description` only from a literal (another `Tool` constructor overload: none); `params` from a JSON-schema string literal, else empty (unknown); `handler` = the method of a method reference (`this::calc`), a lambda gives only its line | A tool specification is server-side by definition |
| C# `[McpServerTool(Name = …)]` with `[Description(…)]` (`ModelContextProtocol`) | Binding | `mcp_tool`, `framework: mcp-csharp`, at the attribute; `endpoint` = `Name`, else the name the SDK derives from the method (SDK 0.3+): a trailing `Async` dropped when it returns `Task` / `ValueTask` / `IAsyncEnumerable`, other characters than ASCII letters and digits → `_`, then snake_case as `JsonNamingPolicy.SnakeCaseLower` (`GetWeatherAsync` → `get_weather`, `GetHTTPStatus` → `get_http_status`); `description` = `[Description]`, else the XML `<summary>`; a parameter is optional only with a default; `CancellationToken`, `IMcpServer` / `McpServer`, `RequestContext<…>`, `IProgress<…>`, `IServiceProvider`, `[FromServices]` skipped | The SDK's own attribute |
| Kotlin `@McpTool` / Spring AI `@Tool` on a `fun`, with `@McpToolParam` / `@ToolParam` | Binding — the Java rules above, Kotlin syntax: `@Tool` only in a module whose build file declares an MCP server starter, and only Spring AI's | `mcp_tool`, `framework: spring-ai-mcp`, at the annotation; `endpoint` = `name`, else the function name; `required` from the annotation only, true by default (Kotlin nullability and a default value do not reach Spring AI's schema), `default` = the default's source text (200 characters at most) | As for Java |
| Kotlin `McpServerFeatures.SyncToolSpecification(tool) { exchange, args -> … }` / `AsyncToolSpecification` / their builders (MCP Java SDK) | Binding | `mcp_tool`, `framework: mcp-java-sdk`; the Java rules above (no `new`; a `val` / `var` declared once in the file; a JSON-schema literal may end in `.trimIndent()`; `handler` = a callable reference `::calc` / `this::calc`, a lambda gives only its line) | A tool specification is server-side by definition |
| Kotlin `<server>.addTool(name = …, description = …, inputSchema = Tool.Input(…)) { … }`, positional `addTool(name, description) { … }`, or `addTool(Tool(name = …, …)) { … }` (official Kotlin SDK, `io.modelcontextprotocol.kotlin.sdk`) | Binding — only in a file that imports the SDK's server package (`io.modelcontextprotocol.kotlin.sdk.server`) | `mcp_tool`, `framework: mcp-kotlin`, at the call; no `inputSchema` → `params` `[]`; a `Tool.Input(…)` / `ToolSchema(…)` whose `properties` is `buildJsonObject { putJsonObject("a") { put("type", …); put("description", …) } }` and `required` a `listOf("…")` → its params; any other schema → `null` (unknown); `handler` = a callable reference, a lambda gives only its line | `addTool` without the SDK's import is not a tool |
| Kotlin `<server>.addTools(listOf(RegisteredTool(Tool(name = …, description = …, inputSchema = …)) { … }, …))` (also `mutableListOf` / `arrayOf`; `RegisteredTool(tool = …, handler = …)` or a positional handler: a lambda or a callable reference) | Binding — same import gate as `addTool`, and only for a list written inline | One `mcp_tool` per `RegisteredTool` element, at the element, read as `addTool(Tool(…))` (`Tool(…)`'s named arguments only); an element that is not a literal `RegisteredTool(Tool(…), …)` is skipped | A list from a variable or a call (`addTools(myTools)`, `addTools(build())`) cannot be read: no record |
| Kotlin import aliases (`import org.springframework.ai.tool.annotation.Tool as AiTool`, `import io.modelcontextprotocol.kotlin.sdk.Tool as McpTool`, …) | — | The alias counts exactly as the class it names (`@AiTool` = Spring AI's `@Tool`, same starter gate) when that class is in `org.springframework.ai.*`, `org.springaicommunity.mcp.*` or `io.modelcontextprotocol.*` | An alias of any other class (`import com.acme.Tool as AiTool`) is never an MCP type, and hides the name it takes |
| Go `mcp.NewTool(name, mcp.WithDescription(…), mcp.WithString(…, mcp.Required(), mcp.Description(…), mcp.Default…(…)), …)` (`mark3labs/mcp-go`) | Binding | `mcp_tool`, `framework: mcp-go`, at `NewTool`; `params` from the `With<Type>` options, `null` (unknown) when an option is not one of them nor a known non-parameter option (description, title, annotations, output schema); `handler` = the second argument of the `AddTool`, or the `Handler` of the `server.ServerTool{Tool: …, Handler: …}` literal (also an element of `[]server.ServerTool{…}`), that registers it: directly, or through its variable — the registration of it after the assignment in the same function and before the variable is reassigned (several disagreeing → null); a package-level variable: the one registration from a function that does not declare its own variable of that name, only when nothing reassigns it (otherwise null); `mcp.NewTypedToolHandler(fn)` / `server.NewTypedToolHandler(fn)` → `fn` | The `mcp` package of mcp-go, under any import name |
| A computed tool name (`name=NAME`, `Name = Const`, `addTool(name = computed())`) | None | — | The tool exists, but its name is unknown |
| `@agent.tool` (pydantic-ai), LangChain `StructuredTool`, Spring AI `@Tool` without an MCP server, `.tool(…)` on any other object | None | — | Not an MCP server tool |

**Incremental sync** (`/api/analyze-diff`): unchanged files are materialised empty, so the proof a changed tools file needs from another file is fetched with real content (not streamed): the build files (`pom.xml`, `build.gradle[.kts]`) in a changed Java or Kotlin file's folder and its ancestors, and the modules a changed Python file with an `@x.tool` imports from (`from .server import mcp`), at most 50 per sync.

`build.gradle.kts` / `settings.gradle.kts` are scanned as config files (Gradle Kotlin DSL), so the starter is found there too.

Not covered yet (follow-up): Kotlin SDK `addTools(…)` with a list that is not written inline, the low-level APIs (Python `Server.list_tools`, TypeScript `setRequestHandler(ListToolsRequestSchema, …)`, the MCP Java SDK's `McpServer.sync(…).tool(…)` / `toolCall(…)` shortcuts), the official Go SDK, `mcp_resource` / `mcp_prompt`, and MCP **client** calls.
