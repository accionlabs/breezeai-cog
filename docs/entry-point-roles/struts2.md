# Struts2 — entry-point roles

Parser: `src/breezeai_cog/parsers/java_struts2/` (`struts.xml` and the files it includes — any
XML whose root is `<struts>` — plus the Convention-plugin annotation detector on Java sources) ·
Rules: [entry-point contract](../architecture/entry-points.md) · Tests:
`tests/unit/test_roles_struts2.py`

Settings are per module (the folder above `src/main/`), so a repository of several applications with different extensions resolves each one. Every Struts2 version reads the same way: 2.0–2.5 and 6.x (`com.opensymphony.xwork2`), 7.x
(`org.apache.struts2`); the DTD version is never checked. An action's address is
`<namespace>/<action name><extension>`: the extension is the first entry of
`struts.action.extension` (default `action`, so `/admin/login.action`; `action,,` still gives
`.action`; an empty first entry gives none).

| Construct | Role | Record | Why |
|---|---|---|---|
| `struts.xml` `<action name="login" class="a.LoginAction" method="save">` in a `<package>` | Binding | `route`, `ANY`, `routeKind: route`, `framework: struts2`, `endpoint` = namespace + name + extension, `handler` = the method, `save` (`method` defaults to `execute`), `handlerPath` / `handlerLine` = the method in `a/LoginAction.java` under the nearest source root above the configuration (`src/main/java`, `src`, `JavaSource`, …); not found, overloaded, or a Spring bean id (`class="loginAction"`) → the method name, no location (the class or bean id stays in `text`) | One handler, inbound HTTP — the record lives at the `<action>` element |
| `<action name="index">` with no `class` | Binding | `route`, `ANY`, endpoint, no handler | Struts runs its own `ActionSupport`; the action only renders its result |
| `<action name="user_*" class="a.{1}Action" method="{2}">` | Binding | `route`, `ANY`, `endpoint` = the pattern as written (`/user_*.action`), no handler when the class or method has a `{n}` | The address pattern is known; which method runs is not |
| `<package namespace="/admin">` | Wiring | no record; the namespace is on each of its actions (`""` and `/` are the top level) | Names no handler |
| `<constant name="struts.action.extension">`, `struts.properties`, the Struts filter's `<init-param>` in `web.xml` | Wiring | no record; the extension is on every action of the module (the folder above `src/main/`), with Struts' precedence — a `<constant>` (this file's, or the classpath root `struts.xml`'s) is overridden by `struts.properties`, which is overridden by the `web.xml` init-param; two sources of the same precedence that disagree leave the endpoint empty | Names no handler |
| `<include file="struts-admin.xml"/>` | Wiring | no record; `importFiles` edge to the included file when it exists beside the including one | Names no handler |
| `@Action("list")` / `@Actions({@Action("a"), @Action("b")})` on a method | Binding | `route` per `@Action` on the annotation, `ANY`, endpoint, `handler` = the method, `handlerLine` = its declaration; a name starting with `/` is absolute; no value or a non-literal value → no endpoint | One handler, inbound HTTP |
| `@Action` / `@Actions` on the class | Binding | as above, `handler` = `execute` | The class's `execute` serves it |
| `@Namespace` / `@Namespaces` on the class, `@Namespace` on `package-info.java` | Wiring | no record; the namespace(s) of the class's actions — one record per namespace; two `package-info` files of one package that disagree → no endpoint | Names no handler |
| A class's default mapping by the Convention plugin — the module's build declares `struts2-convention-plugin`, the package holds a locator (`action`, `actions`, `struts`, `struts2`, or `struts.convention.package.locators`), the class ends in `Action` (or `struts.convention.action.suffix`) or extends `ActionSupport` / implements `Action`, not abstract, has `execute` (declared, or inherited — it extends a class — or `mapAllMatches`) | Binding | `route`, `ANY`, `endpoint` = the namespace (`@Namespace`, `package-info`, else the package segments after the locator) + the Convention name (`UserProfileAction` → `user-profile`), `handler` = `execute`; none when the class or its `execute` has an `@Action` — an `@Action` on another method keeps it (`register.action` beside `@Action("register-input") input()`) | One handler, inbound HTTP |
| A Convention controller under the REST plugin (`struts.mapper.class=rest`) | Binding | one `route` per REST method it declares, with its verb, no extension: `index` `GET /x`, `show` `GET /x/{id}`, `create` `POST /x`, `update` `PUT /x/{id}`, `destroy` `DELETE /x/{id}`, `edit` `GET /x/{id}/edit`, `editNew` `GET /x/new`; `handler` = the method; a controller declaring none → one `ANY` record, no handler | Each REST method is its own handler |
| `<interceptor-ref>` / interceptor stacks, `@InterceptorRef` | Guard | name in `guards` of each action it covers | Run before many handlers — not recorded yet |
| `<result>` of an action or of `<global-results>` | Outbound | `route`, `routeKind: navigation`, `framework: struts2`, `name` = the result name (default `success`), `endpoint` = by type: `dispatcher` (default) / `freemarker` / `velocity` / `plainText` → the view's context-relative path (a relative location is under the package namespace), and the view file, when it exists, is an `importFiles` edge of the configuration; `redirectAction` / `chain` → the target action's address (`namespace` param, else the package's); `redirect` → the path as written, or the action's address when it names an action declared in the same file without an extension (`bookList` → `/bookList.action`) (an absolute URL gives no record); an address that cannot be resolved (a relative location under an unknown namespace, a placeholder) → no record; any other type (`tiles`, `json`, `stream`), and an untyped result in a package extending `tiles-default`, → no record | The action hands the request on: the view it renders or the action it forwards to |
| `@Result` in `@Action(results = …)`, `@Result` / `@Results` on the class | Outbound | as above, on the `@Result`; a relative view `location` is under the Convention result path (`/WEB-INF/content/`, or `struts.convention.result.path`) and the action's namespace, a relative `redirect` / `redirectAction` / `chain` under the action's namespace; a redirect without an extension that names one of the class's actions leads to that action's address; class-level results serve every action of the class | Same |
| An action with no explicit result, mapped by the Convention plugin | Outbound | one navigation record per view file `<web root>/WEB-INF/content/<namespace>/<action>.<ext>` (`name` empty) or `<action>-<result>.<ext>` (`name` = the result), on the action's own construct | The plugin's implicit results |
| JSP `<s:form action>`, `<s:url action>`, `<s:a action>`, `<s:submit action>`, `<s:action name>` (taglib `/struts-tags`) | Outbound | `route`, `routeKind: navigation`, `framework: struts2` on the tag, `endpoint` = the action's address — the tag's `namespace`, else the one namespace whose actions render the page (`struts.xml` results, or a Convention view folder); a namespace not declaring the action falls back to the default namespace (which answers any namespace); a DMI suffix (`save!input`) dropped; also found when written inside another tag's attribute (`<a href="<s:url action='list'/>">`); no namespace known, or a dynamic action (`%{…}`) → no navigation record, the tag stays a plain `element` | Our page calling an action |
| JSP `<a href>`, `<form action>`, `<jsp:forward page>`, `<c:url value>`, `<c:redirect url>`, `<s:url value>`, `<s:a href>` to an action (`.action`, `.do`, the configured extension) or a page (`.jsp`, `.jspx`), or without an extension when it names a declared action and the extension list allows a bare address (Struts' default `action,,`) | Outbound | `route`, `routeKind: navigation`, `framework: jsp`, `endpoint` = the path, `${pageContext.request.contextPath}` / `<%= request.getContextPath() %>` dropped; a relative path resolves against the page's URL (a page under `WEB-INF`: against the namespace of the action rendering it); a dynamic or unresolvable target, an external URL or another file type → no record | Same |
| Dynamic method invocation (`login!save.action`), `<allowed-methods>` | None | — | The methods it can reach are not enumerable from the configuration |
| Struts 1 `struts-config.xml` (`<struts-config>`) | None | — (the `config` parser keeps the file) | A different framework |
