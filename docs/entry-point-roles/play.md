# Play — entry-point roles

Parser: `src/breezeai_cog/parsers/scala_play/` (`conf/routes`, `conf/*.routes` and Scala sources) · Rules: [entry-point contract](../architecture/entry-points.md) · Tests: `tests/unit/test_roles_play.py`

| Construct | Role | Record | Why |
|---|---|---|---|
| `conf/routes` line `VERB /path controllers.C.action(...)` | Binding | `route`, HTTP verb, `routeKind: route`, path, `handler` = `action`, `handlerPath` = the controller's file, `handlerLine` = the action — the controller is a `<Class>.scala` / `.java` under the project's `app/` whose `package` is the route's; not found, in two files or overloaded (Play's own `controllers.Assets`) → `handler` as written, no location | One handler, inbound API — the record lives at the routes line |
| `conf/routes` line `-> /prefix some.Router` | Wiring | no record when it names a routes file of the repo (`admin.Routes` = `conf/admin.routes`, with at least one line) under a resolved prefix: the prefix is on that router's bindings, chained through nested includes. Any other router — a SIRD class, a generated gRPC router — keeps a `route`, `routeKind: mount`, `ANY` record, `handler` = the router (the Target Spec's current form); a SIRD class's bindings get the prefix too. The routes file is looked up in the include's own project (`<project>/conf/`) first, else in the one other project that has it; two other projects have it → it can't be told which, paths as written. Included twice or not at all → paths as written | Points at a router |
| `conf/routes` line `-> /webjars webjars.Routes` | Binding | `route`, `GET`, `endpoint` = the prefix, no handler | The WebJars module serves the assets |
| Controller method returning `Action { … }` / `Action.async { … }` | None | — (it is the handler of a routes line) | Has no address of its own |
| SIRD: `case GET(p"/x") => controller.action` in a `SimpleRouter` | Binding | `route`, HTTP verb, path, `handler` = `action`, `handlerPath` / `handlerLine` = the controller method — the receiver's declared type in the router class (`controller: PostController`), resolved as Scala does — fully qualified, an explicit import, else the one class of that name in the router's package and wildcard imports — to one Scala file; an untyped receiver, a name declared with two types in the class, a class name found in both the package and a wildcard import, a type not in the repo or an overloaded method → no location | One handler, inbound API |
| SIRD: `case GET(p"/x") => Action { … }` — the action written inline (any call given a `{ … }` block, or a curried `Action(parse.json) { … }`) | Binding | `route`, HTTP verb, path, no `handler`, `handlerLine` = the inline action (anonymous) | One handler, inbound API; it has no name, so the action's builder (`Action`) is not one |
| `EssentialFilter` / `Filter`, `ActionBuilder` / `ActionFilter` | Guard | name in `guards`; no record of its own | Run before many handlers |
| `WSClient` calls | Outbound | `api_call` | Our code calling out |
