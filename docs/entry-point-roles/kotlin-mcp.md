# MCP Kotlin SDK — entry-point roles

Parser: `src/breezeai_cog/parsers/kotlin_mcp/tools.py` (additive detector); the JSON-schema reader and the Kotlin literal helpers are in `parsers/jvm_mcp_common.py` · Rules: [entry-point contract](../architecture/entry-points.md) · Tests: `tests/unit/test_roles_kotlin_mcp.py`

A tool a Kotlin MCP server registers in code: with the official Kotlin SDK (`io.modelcontextprotocol.kotlin.sdk`, `framework: kotlin-mcp`), or with a tool specification of the MCP Java SDK (`framework: java-mcp`, as in the [Java table](java-mcp.md)). An annotated Spring AI tool in Kotlin is in the [Spring AI table](spring-ai-mcp.md). The fields of an `mcp_tool` record, how `params` is read and limited, and what an incremental sync does are the same for every MCP framework: [entry-point contract, MCP tools](../architecture/entry-points.md#mcp-tools).

| Construct | Role | Record | Why |
|---|---|---|---|
| `<server>.addTool(name = …, description = …, inputSchema = Tool.Input(…)) { … }`, positional `addTool(name, description) { … }`, or `addTool(Tool(name = …, …)) { … }` (official Kotlin SDK, `io.modelcontextprotocol.kotlin.sdk`) | Binding — only in a file that imports the SDK's server package (`io.modelcontextprotocol.kotlin.sdk.server`) | `mcp_tool`, `framework: kotlin-mcp`, at the call; no `inputSchema` → `params` `[]`; a `Tool.Input(…)` / `ToolSchema(…)` whose `properties` is `buildJsonObject { putJsonObject("a") { put("type", …); put("description", …) } }` and `required` a `listOf("…")` → its params; any other schema → `null` (unknown); `handler` = a callable reference, a lambda gives only its line | `addTool` without the SDK's import is not a tool |
| `<server>.addTools(listOf(RegisteredTool(Tool(name = …, description = …, inputSchema = …)) { … }, …))` (also `mutableListOf` / `arrayOf`; `RegisteredTool(tool = …, handler = …)` or a positional handler: a lambda or a callable reference) | Binding — same import gate as `addTool`; the list written inline, a `val` holding one, or a same-file function returning one | One `mcp_tool` per `RegisteredTool` element, at the element, read as `addTool(Tool(…))` (`Tool(…)`'s named arguments only); an element that is not a literal `RegisteredTool(Tool(…), …)` is skipped. `addTools(x)`: `x` the innermost `val` visible there (a local declared before the call, a class property, a top-level one) initialised by `listOf(…)` / `arrayOf(…)`, or `mutableListOf(…)` when the name is used nowhere else where it is visible than as `addTools`' argument; `addTools(build())`: `fun build() = listOf(…)` or `{ return listOf(…) }` alone, without parameters. A list passed to several `addTools` calls gives one record per element | Anything else cannot be read: no record — a `var`, a mutable list something adds to / removes from / clears (in its block; anywhere in the file for a property), a name bound nearer than the `val` (a parameter, a class's primary-constructor parameter, a `for` loop variable, a `catch` parameter, a `when (val …)` subject), `buildList { … }`, `+`, a function with arguments or a body of more than the `return` |
| `McpServer.sync(transport)….tool(tool) { exchange, args -> … }` / `.toolCall(tool, ::handler)`, also `McpServer.async(…)` (MCP Java SDK) | Binding — only on a chain that starts at `McpServer.sync(` / `.async(`, with `McpServer` imported from `io.modelcontextprotocol.server` (by name, `.*` or an `as` alias, and no other `McpServer` imported; with only `.*`, no `McpServer` class, object or `typealias` declared in the file or, in Kotlin or Java, in its package — unknown, so not proven, when the Kotlin or Java index failed) or written fully qualified | `mcp_tool`, `framework: java-mcp`, at the `.tool` / `.toolCall` name; the tool and handler as in the row below; `.tools(spec…)` is not read (each spec is recorded where it is built) | The server builder registers the tool directly |
| `McpServerFeatures.SyncToolSpecification(tool) { exchange, args -> … }` / `AsyncToolSpecification` / their builders (MCP Java SDK) | Binding | `mcp_tool`, `framework: java-mcp`; the rules of the [Java table](java-mcp.md) (no `new`; a `val` / `var` declared once in the file; a JSON-schema literal may end in `.trimIndent()`; `handler` = a callable reference `::calc` / `this::calc`, a lambda gives only its line) | A tool specification is server-side by definition |
| Import aliases (`import io.modelcontextprotocol.kotlin.sdk.Tool as McpTool`, …) | — | The alias counts exactly as the class it names when that class is in `io.modelcontextprotocol.*` | An alias of any other class (`import com.acme.Tool as McpTool`) is never an MCP type, and hides the name it takes |
| A computed tool name (`addTool(name = computed())`) | None | — | The tool exists, but its name is unknown |
| `addTool` / `addTools` in a file that does not import the SDK's server package | None | — | Not an MCP server tool |
| `server.addResource(uri = …, name = …, description = …, mimeType = …) { … }` (or positional, `readHandler =`) / `addResourceTemplate(uriTemplate = …, name = …) { … }` (or a `ResourceTemplate(…)` passed first), in a file importing the SDK's server package | Binding | `mcp_resource`, `framework: kotlin-mcp`, at the call; `endpoint` = the URI / template literal; `name` = `name =` (or the second positional argument) when a literal, else the URI; `params` `[]` for `addResource`, a template's simple `{variables}`; handler = the trailing lambda's line | |
| `server.addPrompt(name = …, description = …, arguments = listOf(PromptArgument(name = …, description = …, required = …))) { … }` (or a `Prompt(…)` passed first) | Binding | `mcp_prompt`, `framework: kotlin-mcp`; `params` from the literal list (no `arguments` → `[]`; anything else → `null`) | |
| The Java SDK's `Sync/Async{Resource,ResourceTemplate,Prompt}Specification` in Kotlin | Binding | `mcp_resource` / `mcp_prompt`, `framework: java-mcp`, read as in the [Java table](java-mcp.md) | |
| A client: the Kotlin SDK's `Client` (imported from `io.modelcontextprotocol.kotlin.sdk.client`; a name declared once, typed `Client` or `= Client(…)`) → `client.callTool(name = "x", …)` / `callTool(CallToolRequest(CallToolRequestParams(name = "x")))` / `readResource(ReadResourceRequest(ReadResourceRequestParams(uri = …)))` / `getPrompt(GetPromptRequest(GetPromptRequestParams(name = …)))` (also `CallToolRequest(name = …)`); the Java SDK's `McpSyncClient` / `McpAsyncClient` as in Java | Outbound | `mcp_call`, `framework: kotlin-mcp` / `java-mcp`, on the call's own statement; no file framework | A `for` or lambda variable of the same name is another declaration (→ none). A star import of `…sdk.client.*` proves `Client` only when no other `Client` is imported by name (`import com.acme.Client`, `… as Client`) or declared in the file (`class` / `object` / `interface` / `typealias Client`): those win. `CallToolRequest("x", args, meta)` → `x`; `(mapper, "x", json)` only when the first argument is not a literal. Detector `kotlin-mcp-client` (`parsers/kotlin_mcp/clients.py`) |

Resource / prompt fields and `params`: [entry-point contract, MCP resources and prompts](../architecture/entry-points.md#mcp-resources-and-prompts); client calls: [MCP client calls](../architecture/entry-points.md#mcp-client-calls).

Not covered yet (follow-up): `addTools(…)` with a list built any other way than the row above.
