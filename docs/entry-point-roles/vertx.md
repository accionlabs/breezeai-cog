# Vert.x (Java and Groovy) — entry-point roles

Parser: `src/breezeai_cog/parsers/vertx_common.py` (shared rules), `java_vertx/`, `groovy_vertx/` · Rules: [entry-point contract](../architecture/entry-points.md) · Tests: `tests/unit/test_roles_vertx.py`

In Java the detection is the additive `vertx` detector (`java_vertx/detector.py`): it runs in whichever Java parser owns the file, so a Spring `@Component` or JAX-RS resource that uses Vert.x gets these records too (each with `framework: vertx`).

| Construct | Role | Record | Why |
|---|---|---|---|
| `router.get("/x").handler(h)` / `router.post(...)` / … on a `Router` | Binding | `route`, HTTP verb, `routeKind: route`, path, `handler` = `h` (anonymous lambda: `handlerLine` only) | One handler, inbound API |
| `router.route("/x").handler(h)` (no verb) | Binding | `route`, `method` empty, path | One handler for every verb |
| Vert.x 2.x `RouteMatcher`: `rm.get("/x", h)`, bare `get(...)` inside `rm.with { }` | Binding | as above; the receiver is a router by name (`router`, `routeMatcher`, `rm`, `route`) or by its declared type (`RouteMatcher routes = …`, `def m = new RouteMatcher()`, a `Router` field or parameter); a receiver known only by its declared type (outside comments) is a router only for a path containing `/`, since one name may be a `Map` in another method (`r.get("customerId")` is no route) | Same construct, older API |
| `router.route().handler(h)` (no path) / `BodyHandler`, `AuthenticationHandler` | Guard | name in `guards` on the router's bindings; no record of its own | Runs before many handlers |
| `router.route("/api/*").subRouter(sub)` / `mountSubRouter("/api", sub)` | Wiring | statement stays plain (the `route("/api/*")` call is no route); prefix on `sub`'s bindings — `sub` a variable or a field (`this.sub`). `sub` a router factory call (`UserApi.router(vertx)`, a method that creates a `Router`, adds routes and returns it): the factory's bindings get the prefix, in any file (`vertx.mounted-factories`); a factory never mounted (the main router) keeps its paths. A prefix that does not resolve, a router mounted at two prefixes, or a mount on a sub-router's sub-router → empty `endpoint` | Points at a router |
| `eventBus.consumer(addr, h)` / `localConsumer` / 2.x `registerHandler` / `registerLocalHandler` | Binding | `eventbus_consumer`, address as `endpoint`, `handler` = `h`; `h` = `this` (the class implements `Handler`) gives `handler` = `handle` and its line; Java `h` = `new LoadHandler(…)` gives `handle` with `handlerLine` / `handlerPath` of that class, in any file. A class that implements `Handler` but is never registered has no address → no record | One handler, inbound message |
| A method or constructor (any file, any visibility; 2.x and 3.x+) that passes one of its parameters straight on as the address of `registerHandler` / `consumer` / `send*` / `publish` — directly, through a field set by the constructor for the class to register itself (`this.address = address` … `registerHandler(address, this)`), or by relaying it to another such method (an overload) | Wiring | each call of it (`Helper.m(…)`, `m(…)`, a variable of that type, `new Handler(…, addr)`) is a record, with its own argument folded; not foldable → `endpoint` empty; handler = the handler argument, or `handle` of the class for a constructor passing `this`. A helper that rewrites the address (`"x/" + address`), or one declared with a different shape in two files, is not followed. A send / publish through a constructor-set field (an event-bus proxy) stays at its own call site. The helper's own call keeps its record (address unknown), so a helper never called, or called only from files without a Vert.x marker, is still recorded. Only a declaring file naming `org.vertx` or `io.vertx` counts | The helper's address is a parameter |
| 2.x registration table: `map.put(KEY, new X())` where the map's keys reach `registerHandler` (`for (… e : map.entrySet())` + `e.getKey()`, or `for (… k : map.keySet())`) | Binding, one per `put` | `eventbus_consumer`, `endpoint` = KEY folded (constants across files included), `handler` = `handle` of `X` (located in its file); a value that is not `new X(…)` → no handler. The loop's own `registerHandler` is wiring. A map whose keys never reach `registerHandler`, or a handler class that is never `put`, gives nothing | Each put registers one handler |
| Java handler built by a static factory: `router.get("/x").handler(SessionHandler.create(o))`, `consumer(addr, X.create())`, a registration-table value `X.create()` — where the factory's body is only `return new T(…)` | (as the binding) | `handler` = `handle` of `T`, with `handlerLine` / `handlerPath` of that class, in any file (`vertx.handler-factories`). A factory with any other statement (a cache, a condition), an instance method, one returning an anonymous class, a library factory (`BodyHandler.create()`) or a same-named class of another package → no handler. Groovy factories are not followed | The factory's body says which class runs |
| `vertx.setPeriodic(ms, h)` / `vertx.setTimer(ms, h)` | Binding | `timer`, `method: PERIODIC` / `TIMER`, interval as `endpoint`, `handler` = `h` | One handler, triggered by a schedule |
| `new ServiceBinder(vertx).setAddress(addr).register(Iface, impl)` | Binding, one per service method | `eventbus_consumer`, `endpoint` = address, `handler` = the method (from the interface, any file; `handlerPath` / `handlerLine` = that method in the implementing class passed to `register` — `new Impl(…)` or a local assigned one; `default` / `static` / `@ProxyIgnore` methods are not proxied); the interface is resolved as Java would: a single-type import, else the one known service interface among the enclosing types, the file's package and each `import pkg.*` (`Outer.Inner` resolves `Outer` that way); none, several, or a wildcard match shadowed by a same-package type → one record, no handler | A service on a message address |
| `new ServiceProxyBuilder(vertx).setAddress(addr).build(Iface)` | Outbound | `eventbus_send`, `endpoint` = address | A client of that service |
| `@ProxyGen` interface | None | — | Service contract only |
| `eventBus.send` / `request` / 2.x `sendWithTimeout` | Outbound | `eventbus_send` | Our code sending |
| `eventBus.publish` | Outbound | `eventbus_publish` | Our code publishing |
| 2.x `HttpClient` (`org.vertx.java.core.http.HttpClient` variable, or an in-file method returning one): `get` / `getNow` / `post` / `put` / `delete` / `head` / `options` / `patch` / `trace` / `connect` / `request(method, uri, …)` | Outbound | `api_call`, `method`, `endpoint` = URI folded, else empty; never `db_method_call` | Our code calling an HTTP service |
| `vertx.deployVerticle(...)` / 2.x `container.deployWorkerVerticle(...)` / `container.deployModule(...)` | None | (structural `verticle_deploy` statement) | Start-up |
| `vertx.createHttpServer()…listen(port)` | None | — | Start-up |
