# Vert.x (Java and Groovy) — entry-point roles

Parser: `src/breezeai_cog/parsers/vertx_common.py` (shared rules), `java_vertx/`, `groovy_vertx/` · Rules: [entry-point contract](../architecture/entry-points.md) · Tests: `tests/unit/test_roles_vertx.py`

In Java the detection is the additive `vertx` detector (`java_vertx/detector.py`): it runs in whichever Java parser owns the file, so a Spring `@Component` or JAX-RS resource that uses Vert.x gets these records too (each with `framework: vertx`).

| Construct | Role | Record | Why |
|---|---|---|---|
| `router.get("/x").handler(h)` / `router.post(...)` / … on a `Router` | Binding | `route`, HTTP verb, `routeKind: route`, path, `handler` = `h` (anonymous lambda: `handlerLine` only; Java anonymous class `new Handler<…>() { … }`: `handle`, with the line of that class's `handle` Function — the same for consumers, forwarders and registration-table values) | One handler, inbound API |
| `router.route("/x").handler(h)` (no verb) | Binding | `route`, `method` empty, path | One handler for every verb |
| A route path with a part read at runtime: `router.get(pathPrefix + "/request")`, a Groovy `"${prefix}/x"`, `"/api/" + version + "/x"`, or a route under a sub-router mounted once at a prefix that does not resolve | Binding | each such part marked where it stands, named after its source: `${pathPrefix}/request`, `${config:pathPrefix}/request` (`config().getString("pathPrefix")`), `/api/${version}/x`, `${p}/users`. A sub-router mounted at two places: empty | The value is read at runtime; never guessed, never a `{…}` parameter ([contract §6](../architecture/entry-points.md#a-part-read-at-runtime-name)) |
| An address built with `String.format(fmt, …)` / `fmt.formatted(…)` (Java): `router.post(String.format(ENDPOINT.NOTICE, prefix))`, `send(String.format("%s.ready", address), …)`, 2.x `client.get(String.format("%s/%s", base, id), h)` | as the address's kind | read as the same concatenation: the format folded to its text (a literal or a constant, an interface field included), each `%s` / `%d` filled with its argument (`${prefix}/notice`, `${address}.ready`, `${base}/{id}`). A format that does not fold, any other conversion (`%05d`, `%x`, `%1$s`) or a wrong argument count: not read | The code builds the address from known text ([contract §6](../architecture/entry-points.md#a-part-read-at-runtime-name)) |
| A route path that is one value: `router.get(path).handler(h)`, `router.get(this.basePath).handler(h)`, `router.get(config().getString("p")).handler(h)`, 2.x `rm.get(path, h)` (Java) | Binding | `${path}`, `${basePath}`, `${config:p}`; a local assigned once from a configuration / environment read is named after it (`${config:p}`). Only on a router the file declares (`Router.router(vertx)`, `new RouteMatcher()`, a `Router` / `RouteMatcher` field or parameter), with a handler, and the path a name, a field or a configuration / environment read; `route(HttpMethod.GET, path)` and any other call are not read as a path | The value is read at runtime ([contract §6](../architecture/entry-points.md#a-path-that-is-one-value)) |
| `router.get("/x").failureHandler(h)`, with no `handler` / `blockingHandler` on the same chain | Chain step, or None | in a chain on that path (the row "One path registered several times"): a step with `phase: "failure"`; otherwise the statement stays plain, no `route` | `h` runs only when a guard or a step of the path fails (`ctx.fail(…)`), instead of the remaining steps; no request lands on it |
| Vert.x 2.x `RouteMatcher`: `rm.get("/x", h)` (also `trace`, `connect`; `rm.all("/x", h)` serves every verb, `method` empty), bare `get(...)` inside `rm.with { }` | Binding | as above; the receiver is a router by name (`router`, `routeMatcher`, `rm`, `route`) unless this file declares that name with another type (`Map<String, String> router2`), or by its declared type (`RouteMatcher routes = …`, `def m = new RouteMatcher()`, a `Router` field or parameter); a receiver known only by its declared type (outside comments) is a router only for a path containing `/`, since one name may be a `Map` in another method (`r.get("customerId")` is no route) | Same construct, older API |
| A regex path: 2.x `rm.getWithRegEx("/g/.*", h)` / `allWithRegEx`, 3.x+ `router.getWithRegex(…)` / `routeWithRegex(…)` | Binding | `route`, `isRegex` true, `endpoint` the pattern as written (empty when it is not a constant string; a `{n}` quantifier is never read as a runtime part) | Same binding, matched by a pattern |
| `router.route().handler(h)` / `router.post().handler(h)` (no path) — e.g. `BodyHandler`, `LoggerHandler` | Guard | name in `guards` of the bindings registered after it on the same router, in the same method (in a statement list the route is in or nested in): every verb for `route()`, only that verb for `post()` / `get()` / …; no record of its own. Left out when it or the route has `.order(n)` / `.last()` (Vert.x then runs them in another order than written), and when it is an inline lambda (no name). Registered in another method or file (a router passed in): not followed, so the route's `guards` may be incomplete | Runs before every later route it matches |
| A Vert.x-web library handler chained ahead of the route's first app handler: `router.post(p).handler(BodyHandler.create()).handler(h)` (a class imported from `io.vertx.ext.web.handler`, by name or through `io.vertx.ext.web.handler.*` when no import by name, class of the file or class of its package has that name; built by `X.create(…)` or `new X(…)`) | Guard | its name in `guards`, after the path-less ones. After an app step it is a step of the chain, by name only | Library middleware |
| One path registered several times with the app's own handlers: `router.post(p).handler(a)`, `router.post(p).handler(b)`; and on one statement, `.handler(a).handler(b)` (also `blockingHandler`) | Binding (the first), Chain step (the others) | **one** `route` at the first registration: `handler` / `handlerLine` / `handlerPath` the first app step's, every step in `handlerChain` in registration order (`{name, handler, handlerLine, handlerPath}`; a library handler or a class not in the repository: name only; an inline lambda: its line only), then each `.failureHandler(h)` on the path with `phase: "failure"`; written when there are 2 or more steps or a failure handler. Only when it is certain ([contract §3](../architecture/entry-points.md#one-chain-one-binding)): the same router variable, verb and path expression, in one statement list, no `.order(n)` / `.last()`, no differing `.produces()` / `.consumes()` / `.virtualHost()`, not mixed with `route(p)` / `route(HttpMethod.X, p)` / `.method(…)` on the path, not under a mounted sub-router, nothing registered between them that might match the path (a path-less registration of the verb, a regex route, a mount, a path not certainly different). Otherwise one `route` per registration, each with its own last `handler`. Java only; a 2.x `RouteMatcher` route takes one handler | Vert.x-web runs each matching route in order (`ctx.next()`) |
| `router.route("/api/*").subRouter(sub)` / `mountSubRouter("/api", sub)` | Wiring | statement stays plain (the `route("/api/*")` call is no route); prefix on `sub`'s bindings — `sub` a variable or a field (`this.sub`). `sub` a router factory call (`UserApi.router(vertx)`, a method that creates a `Router`, adds routes and returns it): the factory's bindings get the prefix, in any file (`vertx.mounted-factories`); a factory never mounted (the main router) keeps its paths. A prefix that does not resolve, a router mounted at two prefixes, or a mount on a sub-router's sub-router → empty `endpoint` | Points at a router |
| `eventBus.consumer(addr, h)` / `localConsumer` / 2.x `registerHandler` / `registerLocalHandler` | Binding | `eventbus_consumer`, address as `endpoint`, `handler` = `h`; `h` = `this` (the class implements `Handler`) gives `handler` = `handle` and its line; Java `h` = `new LoadHandler(…)` gives `handle` with `handlerLine` / `handlerPath` of that class, in any file. A class that implements `Handler` but is never registered has no address → no record | One handler, inbound message |
| A method or constructor (any file, any visibility; 2.x and 3.x+) that passes one of its parameters straight on as the address of `registerHandler` / `consumer` / `send*` / `publish` — directly, through a field set by the constructor for the class to register itself (`this.address = address` … `registerHandler(address, this)`), or by relaying it to another such method (an overload) | Wiring | each call of it (`Helper.m(…)`, `m(…)`, a variable of that type, `new Handler(…, addr)`) is a record, with its own argument folded; not foldable → each unknown part marked where it stands (`${address}`, `orders/${id}`; a local read from config is named after the read, `${config:api-verticle.address}`, [contract §6](../architecture/entry-points.md#a-part-read-at-runtime-name)); handler = the handler argument, or `handle` of the class for a constructor passing `this`. A helper that rewrites the address (`"x/" + address`), or one declared with a different shape in two files, is not followed. A send / publish through a constructor-set field (an event-bus proxy) stays at its own call site. A subclass constructor's `super(…, ADDRESS)` (or `this(…)`) calling a constructor that registers its object is a record on that call: registered as `this` → `handler` = `handle` of the subclass; as `this::onMessage` → `handler` = `onMessage`, located in the subclass when it declares it (an inherited one is not located: a subclass of it may override it); as a lambda → `handlerLine` / `handlerPath` = the lambda in the registering class; a middle class passing its parameter on to `super(…)` is followed like any relay; two constructors of one class on one address give one record. That subclass need not name Vert.x: its `super(…)` / `this(…)` calls are read in any Java file once the repo has such a constructor. Its call sites are read in any Java file that names its class, Vert.x marker or not. A send, publish or registration is recorded where it is made, not where it is defined ([contract §5](../architecture/entry-points.md#where-an-outbound-record-is-written)): inside the helper, the bus call on its own address — its parameter (`sendWithTimeout(address, …)`, `registerHandler(address, handler)`), the field its constructor sets (`registerHandler(address, this)` in `deploy()`), or a relay's `send(…, address, …)` / `super(…, a)` passing it on — is a plain statement, since each call of the helper is that send or registration with its address. A helper never called sends and registers nothing; one declared with a different shape in two files is not followed and keeps its record. Only a declaring file naming `org.vertx` or `io.vertx` counts | The helper's address is a parameter |
| 2.x registration table: `map.put(KEY, new X())` where the map's keys reach `registerHandler` (`for (… e : map.entrySet())` + `e.getKey()`, or `for (… k : map.keySet())`) | Binding, one per `put` | `eventbus_consumer`, `endpoint` = KEY folded (constants across files included), `handler` = `handle` of `X` (located in its file); a value that is not `new X(…)` → no handler. The loop's own `registerHandler` is wiring. A map whose keys never reach `registerHandler`, or a handler class that is never `put`, gives nothing | Each put registers one handler |
| Java handler built by a static factory: `router.get("/x").handler(SessionHandler.create(o))`, `consumer(addr, X.create())`, a registration-table value `X.create()` — where the factory's body is only `return new T(…)` | (as the binding) | `handler` = `handle` of `T`, with `handlerLine` / `handlerPath` of that class, in any file (`vertx.handler-factories`). A factory with any other statement (a cache, a condition), an instance method, one returning an anonymous class, a library factory (`BodyHandler.create()`) or a same-named class of another package → no handler. Groovy factories are not followed | The factory's body says which class runs |
| `vertx.setPeriodic(ms, h)` / `vertx.setTimer(ms, h)` | Binding | `timer`, `method: PERIODIC` / `TIMER`, interval as `endpoint`, `handler` = `h` | One handler, triggered by a schedule |
| `new ServiceBinder(vertx).setAddress(addr).register(Iface, impl)` | Binding, one per service method | `eventbus_consumer`, `endpoint` = address, `handler` = the method (from the interface, any file; `handlerPath` / `handlerLine` = that method in the implementing class passed to `register` — `new Impl(…)` or a local assigned one; `default` / `static` / `@ProxyIgnore` methods are not proxied); the interface is resolved as Java would: a single-type import, else the one known service interface among the enclosing types, the file's package and each `import pkg.*` (`Outer.Inner` resolves `Outer` that way); none, several, or a wildcard match shadowed by a same-package type → one record, no handler | A service on a message address |
| `new ServiceProxyBuilder(vertx).setAddress(addr).build(Iface)` | Outbound | `eventbus_send`, `endpoint` = address | A client of that service |
| `@ProxyGen` interface | None | — | Service contract only |
| `eventBus.send` / `request` / 2.x `sendWithTimeout` | Outbound | `eventbus_send` | Our code sending |
| `eventBus.publish` | Outbound | `eventbus_publish` | Our code publishing |
| 2.x `HttpClient` (`org.vertx.java.core.http.HttpClient` variable, or an in-file method returning one): `get` / `getNow` / `post` / `put` / `delete` / `head` / `options` / `patch` / `trace` / `connect` / `request(method, uri, …)` | Outbound | `api_call`, `method`, `endpoint` = URI folded, else its unknown parts marked (`${uri}`, `/1.0/data/{id}`); never `db_method_call`. A class implementing `HttpClient` that delegates to another client is recorded at its own calls too: each is the real outbound call, and its address is a parameter, so `endpoint` is empty | Our code calling an HTTP service |
| `vertx.deployVerticle(...)` / 2.x `container.deployWorkerVerticle(...)` / `container.deployModule(...)` | None | (structural `verticle_deploy` statement) `endpoint` the deployed name when it is a constant string; a variable, `new X()` or `X.class` leaves it empty | Start-up |
| 2.x module descriptor `mod.json` with `"main": "com.acme.OrdersVerticle"` (deployed by `vertx runmod` / `deployModule`) | None | one `verticle_deploy` on the `mod.json` File, on the `"main"` line: `endpoint` the verticle (a `groovy:` / `java:` prefix stripped), `handler` `start` with its `handlerPath` / `handlerLine` when the class is in the repository and declares `start()` itself (found by its fully-qualified name; a `groovy:` class among Groovy classes first, then Java classes, since the Groovy factory loads a compiled class by name); a script (`app.js`) gets `handlerPath` when it sits next to `mod.json`; no `"main"`: no statement. Only a Vert.x descriptor counts: a verticle factory prefix (`groovy:`), a key only a module descriptor has (`worker`, `multi-threaded`, `includes`, `preserve-cwd`, `auto-redeploy`, `resident`, `system`), or a `"main"` naming a Java or Groovy class of the repository; a `mod.json` with none of these (another tool's) gives no statement | Start-up |
| `vertx.createHttpServer()…listen(port)` | None | — | Start-up |
